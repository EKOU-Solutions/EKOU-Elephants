# Color

<Status status="accepted" detail="Valores de tokens.json; cambia el tema en la barra superior para verlos en vivo" />

Cada color tiene **una sola función**. El riesgo va de claro a oscuro (bajo → alto) para que el orden se lea incluso sin distinguir colores: azul, amarillo y rojo cálido. Lo que no tiene datos lleva trama gris.

<Swatches />

## Roles

| Rol | Tokens | Regla |
| --- | --- | --- |
| Riesgo (mapa, etiquetas) | `risk-low`, `risk-medium`, `risk-high` y `on-risk-*` para el texto | Solo datos. Ordenados de claro a oscuro. |
| Sin datos | `unknown`, `unknown-surface` | Trama gris, siempre con «Sin datos». |
| Texto | `text`, `text-muted` | Ambos pasan 4,5:1. |
| Estructura | `line`, `line-strong`, `control-border`, `map-border` | Las líneas organizan; los controles llevan borde de 3:1. |
| Acción | `action`, `action-hover`, `on-action`, `action-soft`, `focus` | Enlaces, botones y foco. Nunca para riesgo. |
| Mensajes | `warning`, `danger`, `success` y sus versiones `-soft` | Solo mensajes de la interfaz. `success` confirma una acción; nunca dice que un territorio es seguro. |

Excepción registrada (revisión de la Ronda 05): en la barra *Avance frente a lo esperado*, la marca de lo esperado usa `risk-high` como alerta.

## Contraste comprobado

`build.py` comprueba cada par en ambos temas y falla si alguno no pasa (WCAG 2.2 AA: 4,5:1 para texto, 3:1 para controles, foco y trama). «Relieve»: los rellenos del mapa no alcanzan 3:1 contra la superficie a propósito; por eso van siempre con borde entre territorios, leyenda, etiqueta y tabla equivalente.
