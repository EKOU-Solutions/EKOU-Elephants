# Audit: map page mockup and guide v1.1 changes (2026-11-15)

Target: `docs/design/pages/map/` (mockup built by `build.py`, 17 screens) and the uncommitted guide v1.1 changes in `docs/design/guide/components.css` / `components.json`, compared with `main` and with the accepted rules in `guide/design-system.md` and `visual-direction.md`. Requested by the user: "no se están siguiendo los tokens, lineamientos definidos".

Read-only: this audit edits neither the mockup nor the guide.

## Method

- Built the guide and the mockup; inspected screenshots at 320, 390 and 1280 px, light and dark.
- Scanned `components.css` declarations for values a token covers (px, hex, rgba, raw weights and line heights) and diffed the result against `main`.
- Scanned the mockup's own `PAGE_CSS` the same way. The gallery frame (`.bar`, `.gallery`, `.shot`, `.device`, `.desktops`) is excluded because it is review scaffolding, not the page.
- Compared the classes in the generated HTML with `components.json`.
- Checked number formats against the data display contract.

Numbers: `components.css` on `main` already has 161 raw values; the branch adds **48 more** (209 in total). The mockup's page CSS has 22 raw values although its own comment says "tokens only".

## What works (keep)

- Neutral fill, hatch with «Sin datos», selection by outline plus name: matches `visual-direction.md`.
- No overflow at 320, 390, 768 or 1280 px; every control has a name; 44 px controls.
- Light and dark themes both read correctly; copy avoids «corrupción», «robo», «sospechoso».
- Sources: every figure carries its source and period; licences appear once.

## Top 3 changes

1. Downgrade every v1.1 addition to `candidate` and put them to one approval round (finding 1).
2. Replace raw sizes, spacing, weights and line heights with tokens, snapping off-scale values (findings 2–4, 9).
3. Remove shadows and gradients and route the map boundary through a structure token (findings 5–6).

## Decisions needed

- **Map boundary colour (finding 6):** change the value of `--el-color-map-border` for the neutral variant, or add a new token? Either is a guide change that needs approval.
- **Table on narrow screens (finding 5):** allow horizontal scroll with a plain rule as the cue, or drop to two columns at 320 px?
- **Legend position on desktop (finding 15):** right column (current spec §5) or under the map.
- **Panel and sources as catalogue components (finding 12):** promote them, or keep the page CSS to layout only and restyle with existing components.

## Checks not run

- `design:design-critique`, `design:accessibility-review`, `design:ux-copy`: this audit was scoped to tokens and guidelines; the independent critique of the same day (validation.md, iteration 7) covers hierarchy and copy.
- `impeccable detect` was run earlier the same day on the same build: 0 anti-patterns (advisories only), so it was not repeated.
- Screen reader run with real assistive technology.

## User decisions and follow-up (2026-11-15)

Decisions: reuse existing tokens (no new or changed token); the table scrolls; the legend stays where spec §5 puts it; page CSS only places the grid.

Applied in validation.md iteration 8:

- Findings 1 and 13: the additions since the committed v1.1 are now `candidate`: Data help, Text link, Map canvas/tools/selection, Counter rows, Table toggle, Page heading, Territory panel, Sources list. Core entries are back to their committed class lists. Every `el-` class in the mockup is in the catalogue.
- Findings 2–4, 9: sizes, spacing, weights and line heights use tokens; off-scale values snapped (12→14, 15→16, 20→22, 28→26, 2/6/10/18/40 px → space tokens); toggletip icon 20 px.
- Finding 5: no gradients or shadows. The table scroll keeps only the native scrollbar; map names sit on a surface plate.
- Finding 6: boundaries of neutral, «Sin datos» and context shapes use `control-border`, an existing structure token (3.1:1 / 3.7:1 light, 3.4:1 / 4.6:1 dark against `line` / `surface-subtle`). `map-border` keeps its role for risk fills.
- Finding 7: the help rule uses `line-strong`.
- Finding 8: every focus ring uses `--el-focus-offset`.
- Finding 10: percentages as «90,8%».
- Finding 11: the selected key is 3 px (`rule-strong` + `rule`), as on the map.
- Finding 12: the page CSS only places the grid; the review gallery keeps its own scaffolding block.
- Finding 14: inline styles carry only geometry custom properties (`--ar`, `--x`, `--y`) plus the hidden hatch defs.

What remains raw has no token: icon sizes (20 px, set by the icon rule), the 1 px screen-reader technique, the search width cap and the map height caps.

Out of scope, for a later guide fix: v1.0 core components also use raw values (15, 13, 24, 32 px sizes and others; 161 occurrences on `main`).
